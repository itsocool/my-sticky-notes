# 구현 결과와 검증 기록

## 구현 내용

승인된 [계획](implementation-plan.md)에 따라 macOS 오프라인 스티키 노트 앱을 구현했다.
React 목록·검색, Tiptap 서식 편집, SQLite 영구 저장, 독립 창, 7색 팔레트,
노트별 상단 고정, 메뉴 막대, 저장 확인 후 종료, 창 복원과 단일 인스턴스를 연결했다.

SQLite 스키마는 user_version=1이며 기존 파일을 임의 초기화하지 않는다.
내용 저장은 500ms 동안 입력을 모은 뒤 노트별로 직렬 실행한다.
창 이동·색상·고정 변경은 본문 수정 시간을 바꾸지 않는다.

## 결정과 리뷰 반영

- 현재 미커밋 개발 환경을 보존하고 승인된 현재 폴더에서 구현했다. 자동 커밋·게시하지 않았다.
- 편집기는 Tiptap 3의 굵게·기울임·밑줄·취소선·글머리 목록·실행 취소만 활성화했다.
- 편집기 번들을 지연 로드해 목록 창에서 필요 없는 편집기 코드를 로드하지 않는다.
- Browser 플러그인이 세션에 없으므로 Playwright Chromium으로 브라우저 UI를 검증했다.
  IPC 경계는 e2e 테스트 파일에서만 대체하며, 제품에는 브라우저용 가짜 저장소를 넣지 않았다.
- 별도 읽기 전용 리뷰에서 발견한 한글 조합 중 이어지는 저장, 로딩 실패 창의 종료,
  종료 도중 다른 작업 완료에 따른 편집 잠금 해제 문제를 회귀 테스트로 재현하고 수정했다.
- 숨긴 WebView의 저장 확인은 requestAnimationFrame을 기다리지 않는다.
  실제 조합 중인 편집기만 compositionend/blur를 기다리고 최종 문서 상태를 확인한다.
  조합이 끝났음을 확인하지 못하면 닫기·종료를 취소한다.
- 저장하지 못한 본문이 있으면 정상 종료를 취소한다. 이미 본문 저장을 확인한 뒤의
  창 위치 저장 실패는 종료를 막지 않고 마지막으로 저장된 위치를 사용한다.
- 정상 종료 확인 중에는 새 창 생성·열기·삭제를 거부한다. 취소 시 모든 편집 잠금을 해제한다.

## 실제 macOS 앱 검증

- 최종 .app/.dmg 빌드 확인. 개발 실행과 배포 앱을 모두 열어 실제 React 화면과 Rust 호출을 확인했다.
- 검증용 [QA] 노트를 만들고 접근성 입력으로 한글 내용을 저장했다. SQLite를 읽기 전용으로 조회해 문서와 일반 텍스트 저장을 확인했다.
- 색상을 파랑으로 변경하고 상단 고정을 켰다. 네이티브 창의 layer=5와 저장된 pinned=1을 확인했다.
- 창을 숨긴 뒤 목록의 종료로 정상 종료(exit code 0)했다. 숨긴 WebView가 있어도 종료가 지연되지 않았다.
- 다시 열어 같은 노트의 저장 내용·색상·핀을 확인했다. 열린 채 정상 종료 후 다시 실행하자 창이 자동 복원되었다.
- 복원 좌표 1085×487, 크기 320×360과 네이티브 layer=5를 확인했다. 상단 고정 창은 컴퓨터 도구의 기본 창 목록에서 제외되어 CoreGraphics 조회와 해당 window ID로 직접 확인했다.
- 두 번째 앱 실행은 즉시 exit code 0으로 끝나고 기존 앱 프로세스만 유지되었다.
- 검증용 UUID의 메모는 확인 대화상자로 삭제했다. 해당 행과 복원 기록이 제거되었으며 기존 메모 3개는 보존했다.
- 물리 키보드 입력 자동화는 창 포커스 제약 때문에 완료하지 못했다. 네이티브 한글 저장은 접근성 입력으로 확인했고 IME 조합 보호는 회귀 테스트로 검증했다.
- 메뉴 막대 아이콘·항목 생성과 Rust 핸들러는 빌드·실행으로 확인했다. 현재 컴퓨터 도구는 메뉴 막대 조작을 지원하지 않아 항목의 직접 GUI 클릭은 자동화하지 못했다.

테스트 입력의 compositionend가 끝나지 않는 경우 종료를 확인하지 않는 회귀 테스트도 추가했다.
사용자에게 입력 조합을 마치도록 안내하며 미완성 내용을 저장 완료로 오인하지 않는다.

## 시안과 화면 비교

- 시안: [design-concept.png](design-concept.png), built-in Image Gen으로 생성한 비교용 UI 목업.
  제품에는 해당 이미지를 UI로 사용하지 않는다.
- 프롬프트 요약: 한국어 Microsoft Sticky Notes 스타일, 360×640 목록과 320×360 노트,
  플랫한 파스텔 색상, 상단 창 도구, 검색·카드 목록, 하단 5개 서식 버튼. 이미지·마케팅 화면 제외.
- 실제 UI는 React/CSS/Tiptap와 Lucide 벡터 아이콘으로 구성했다. 앱·메뉴 막대 아이콘은 로컬 SVG에서 생성했다.

| 비교 항목   | 확인과 조정                                                                                |
| ----------- | ------------------------------------------------------------------------------------------ |
| 구조        | 작은 목록 창·검색·세로 카드 목록과 독립 편집창 유지                                        |
| 글꼴        | 시스템 글꼴, 목록 제목 14px, 본문 15px, 작은 시간·저장 상태                                |
| 색상        | 파스텔 7색; 어두운 테마에서는 본문을 어둡게, 카드 색상 띠와 노트 헤더를 유지               |
| 간격        | 목록 12px 여백, 노트 16px 본문 여백, 헤더·서식 도구 36px                                   |
| 아이콘      | 일관된 17~19px 선형 아이콘, 의미별 접근성 이름·툴팁·포커스                                 |
| 작은 창     | 240×200에서도 팔레트와 서식 도구 접근 가능; 색상 팝업을 창 안에 배치                       |
| 수정한 차이 | CSS 선택자 충돌로 카드 옵션이 아래에 나오던 문제와 짧은 노트의 불필요한 스크롤 여백을 수정 |

시안과 최신 Playwright 스크린샷을 view_image로 직접 비교했다.
브라우저 스크린샷의 노트는 테스트 픽스처이며 실제 앱에 예제 노트를 자동 생성하지 않는다.

## 제한 사항

- Windows/Linux 빌드·동작, 앱 서명·공증·외부 배포는 검증 범위 밖이다.
- 실제 디스크 공간 부족은 브라우저 경계의 실패 주입으로 검증했으며 OS 디스크를 채우지 않았다.
- 다양한 DPI의 복수 모니터 하드웨어 조합은 자동화 위치 보정 테스트로 완전히 대체되지 않는다.
- 강제 종료·전원 차단 직전의 미저장 입력은 복구를 보장하지 않는다.
- 이미지·계정·클라우드 동기화·자동 업데이트·전역 단축키는 구현하지 않았다.

## Browser 설치 요청

공식 Browser는 현재 ChatGPT 데스크톱 앱에 자동 포함되는 내장 기능이다.
현재 Orca 세션에서 해당 도구를 활성화할 설치 대상은 발견되지 않았다.
확인 중 설치한 동명의 타사 BrowserAct는 공식 Browser와 달라 즉시 제거했다.
[공식 Browser 문서](https://learn.chatgpt.com/docs/browser?surface=app)를 기준으로 확인했으며,
공식 Browser 설치 완료로 보고하지 않는다.

## 최종 빌드

마지막 UI 보정과 IME 조합 종료 확인을 반영한 `npm run tauri build`가 exit code 0으로 완료되었다.

- `.app`: `src-tauri/target/release/bundle/macos/My Sticky Notes.app` (6.38 MiB)
- `.dmg`: `src-tauri/target/release/bundle/dmg/My Sticky Notes_0.1.0_x64.dmg` (3.01 MiB)
- 프런트엔드: 기본 번들 249.57 kB, 지연 로드 편집기 408.03 kB (압축 전)
- 미커밋 상태로 현재 폴더에 보존했으며 원격 게시·병합·자동 커밋을 수행하지 않았다.

최종 배포 앱을 다시 실행해 메모 목록이 표시되고 기존 메모가 유지되는 것을 확인했다.
